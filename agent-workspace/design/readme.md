# design

How Tono should look and behave: the sidebar, the terminals, the palette, dialogs, and how the desktop app, the web app and a phone differ. These documents answer "what are we building and why" before a spec answers "how".

Naming: `design-<nnn>-<slug>.md`

Rules:

- Rex for Mac is the reference. A design that departs from it says where and why.
- A design names the screens and states it covers, so a spec can point at them.
- Same workspace conventions: lowercase kebab-case, permanent numbers, a `Status` field, cross-reference by short code.
